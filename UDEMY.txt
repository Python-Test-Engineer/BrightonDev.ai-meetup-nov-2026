FROM AN AI AGENT IN HTML TO OUR OWN MINI CODER JS

A high level view of how AI agents really work told through a working mini
coder app you can run yourself starting from one HTML file and one fetch call
and ending with a coding agent in your own terminal editing real files in a
real workspace

No frameworks No SDKs No magic Just an API call in a loop and every layer
built on top of it in plain JavaScript

THE PITCH

Most courses teach you to import an agent library and call it This one gives
you the high level view of what that library is doing and shows you a working
mini coder app that does it

You will begin with a single HTML page that sends a POST request to an LLM API
and prints the reply That page is the whole idea Everything else in this
course is the harness around it context tools looping memory a sandbox
lifecycle hooks and finally a working coding agent in Node

By the end you will understand how an agent that can list files read them
create them edit them run shell commands remember what it learned between runs
refuse to write outside its workspace and stop itself when it has done enough
is put together You will have seen that mini coder run and you will have used
it The loop itself is around 120 lines of code with every other concern in its
own small module and that is the app we use as our worked example throughout

The single most important idea in the course fits on a slide

think then model call then tool calls If there are none print the answer and
stop If there are some run the tools append the results and loop back

If you understand that diagram you understand agents and you will recognise it
in every agent you meet afterwards

This course exists because agents look like a different world from ordinary
software and they are not An agent is a REST API call with a payload wrapped
in a loop with a few functions the model is allowed to ask for That is it
Once you see it the mystery is gone and the engineering starts

WHAT YOU WILL LEARN

The core building blocks of every agent

MEMORY The model is stateless Every request must carry the whole
conversation or the agent has no idea what just happened
CONTEXT What you put in front of the model statically or dynamically is
the difference between a clever demo and a useful tool
LOOPING Repeat the call until the model stops asking for tools Remove the
loop and you have a chatbot
TOOL CALLING The model cannot touch a file It emits JSON naming a tool and
your code runs it That is the only way a model can act on the world

The engineering that turns those four into something you would actually use

A sandbox that refuses writes outside the workspace including writes
attempted through the shell
An environment allow list for child processes so a command cannot echo your
API key into the transcript
A bounded step budget so the loop cannot run forever
Errors returned as observations instead of exceptions so the model can
correct itself on the next step
Exit codes from run command so the agent knows whether its code worked
A human in the loop confirm before commands hard deny the destructive ones
Lifecycle hooks so you can extend the agent without editing the loop
Long term memory in a plain markdown file you can read diff and delete
Configuration precedence you can explain flag beats dot env and dot env
beats shell

The mindset which is the real subject

PROMPT ENGINEERING becomes CONTEXT ENGINEERING becomes HARNESS ENGINEERING
A better harness with a weaker model beats a weak harness with a stronger
model Many times the harness is the deciding factor
Look at the patterns and the structure not the syntax The syntax you can
look up The shape is what you are here to learn

Python developers who are comfortable with the ideas and want to see them in

REQUIREMENTS

A modern browser
Node 20 or newer for the second half of the course
An OpenRouter account and an API key Any model that supports tool calling
will do and the course shows how to swap models with one environment
variable
Python is optional and only to serve the HTML pages over HTTP There is no
build step anywhere in this course

A note on the key the HTML demos read it from a local file at runtime That is
fine for learning on your own machine and the course says plainly why it is
not how you would ship it The Node agent reads it from dot env never prints
it and never passes it to a child process

HOW THE COURSE IS TAUGHT

This is a high level view with a working mini coder app It is not a code along

We do not go deep into the code and we do not type it out together line by
line The code is there to make the ideas concrete We show you the shape of it
the part that carries the idea and we move on The full explanations the detail
the edge cases and the reasoning behind each decision live in the ebooks that
accompany this course and those are where you go when you want the depth

What you do get is a complete working mini coder app You see it run on real
tasks you see it read and write real files and you see it stop itself when it
should That working app is the anchor for every concept in the course A
concept is not just described it is pointed at in something that already runs

Think of every code sample as an illustration You are not here to memorise it
You are here to see the pattern so that when you meet the same pattern in a
framework or in your own codebase you recognise it immediately

Each concept arrives in the order you would meet it if you were building this
yourself First the smallest thing that works then the problem that appears
then the smallest fix for that problem Nothing is introduced before the reason
for it is on screen

We also use AI tools to modify and explore the codebase with you That is part
of the method not a shortcut around it We ask the agent to explain a file to
summarise a module to change a setting to break something on purpose and then
we read what came back and judge it That is exactly the skill this course is
built around and it is the same skill you will use on your own projects

So you will see code run you will see it change you will see it fail and you
will see it fixed but you will not be copying it down The code you finish with
is not a toy you throw away It is a working harness you can point at your own
workspace extend with your own tools and grow into whatever you need next and
the ebooks are your reference for the parts we only sketched on screen

THE ONE THING TO TAKE AWAY

An agent is a loop around a model call with a handful of functions the model is
allowed to ask for and a harness that decides what those functions may touch

Everything else is engineering you already know how to do
